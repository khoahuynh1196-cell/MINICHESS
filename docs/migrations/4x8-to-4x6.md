# 4x8 to 4x6 compatibility

The production contract is `production-4x6-0.1.0` with 24 global cells:
enemy `0..11` and player `12..23`. The legacy `alpha-0.3.0` 4x8 state is not
silently truncated.

## Board mapping

Legacy player formation state has 16 local entries. The first three rows are
retained (`0..11`); the fourth row (`12..15`) must be empty. An occupied fourth
row returns `LEGACY_BOARD_CELL_OUTSIDE_CANONICAL_BOUNDS` and the original state
is left untouched.

Legacy global replay positions map as follows:

| Legacy position | Canonical result |
| ---: | :--- |
| `0..11` | unchanged |
| `16..27` | `12..23` (`12 + position - 16`) |
| `12..15`, `28..31` | rejected |

Values outside `0..31`, non-integers, missing schema metadata, and unsupported
versions are rejected. A canonical envelope is idempotent: reading it does not
run the legacy mapper again.

## Persistence boundary

New PostgreSQL writes use:

```json
{
  "schema_version": "production-4x6-0.1.0",
  "view": { "contentVersion": "alpha-0.4.0", "board": ["..."] }
}
```

Legacy envelopes are migrated on read only when every occupied cell maps. A
rejected legacy envelope returns no run to the application; callers must show a
recoverable incompatible-save message rather than inventing a position.

## Local saves and replays

Godot local saves require schema `2` and the canonical ruleset version. Older
schema-1 saves are rejected with a reset/recovery path. Replay files accept the
explicit legacy schema only through the position mapper; an invalid tail cell
causes the replay to be rejected. The checked-in demo replay is already
canonical.
